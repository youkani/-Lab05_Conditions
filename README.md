string GetHint(int difference) {
    switch (difference) {
        case <= 3:
            return "🔥 Горячо!";

### Ответы на вопросы:

**1. Чем int.TryParse() безопаснее int.Parse()? В каких случаях стоит использовать каждый?**
`int.Parse()` при попытке обработать некорректную строку (например, буквы "abc" вместо числа) вызывает ошибку (исключение `FormatException`) и программа аварийно завершается. `int.TryParse()` просто возвращает `false`. Стоит использовать `int.TryParse()` всегда при обработке внешних данных и ввода пользователя с клавиатуры, где высока вероятность опечатки. Использовать `int.Parse()` можно только когда уверен в формате строки (например, если строка генерируется самой системой внутренне и не зависит от человека).

**2. Когда switch удобнее, чем цепочка if/else if? Приведите пример из реальной жизни.**
`switch` удобнее, когда выполняется проверка одного и того же значения на равенство конкретным константам. Код выглядит чище без постоянного дублирования имени переменной. Пример из жизни это обработка нажатия клавиш в игре. Писать под каждую клавишу `else if` слишком громоздко.

**3. Что произойдёт в switch, если убрать break после одного из case?**
Компилятор выдаст ошибку компиляции. Язык C# запрещает сквозное выполнение, если в ветке `case` написан какой-либо исполняемый код. Исключение это пустые `case`, которые группируются подряд, тогда управление переходит к общему для них блоку кода с `break`.

**4. Чем отличается = от == в C#? Почему это частая ошибка?**
`=` это оператор **присваивания** (записывает значение правого выражения в левую переменную). `==` это оператор **сравнения** (проверяет значения на равенство и возвращает результат типа `bool`).
Это частая ошибка, потому что в математике один знак равенства используется для сравнения. Написание `if (x = 5)` в C# приведет к ошибке компиляции, так как результатом присваивания не является логический тип `bool`.

**5. Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.**
Да, это возможно. В лабораторной работе использовался пример вложенного тернарного оператора:
`string weather = temp >= 20 ? "тепло" : (temp >= 0 ? "прохладно" : "мороз");`
Читаемость кода низкая. В нём легко допустить логическую ошибку.
